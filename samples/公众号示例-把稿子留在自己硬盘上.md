# 把稿子留在自己硬盘上

[toc]

> 工具应当消失在句子后面。
> 你要记住的是观点，不是软件的 logo。

今天写字的人，很少缺「另一个编辑器」。
缺的是：**写完之后，文件还是不是你的。**

## 一、云笔记的隐形账单

同步很方便。方便的代价通常是这三样：

1. **账号** — 服务没了，导出流程突然变得很长
2. **格式** — 私有块结构、专有数据库，离开 App 就难读
3. **默认联网** — 你甚至说不清，某次自动保存经过了哪台服务器

对日记、小说、未发表的商业文案来说，这不是强迫症，是基本风险控制。

## 二、Markdown 仍是最稳的中间态

Markdown 不完美。它的表格别扭，脚注各家方言不同，复杂排版要靠约定。

但它有一个别的格式很难替代的优点：

**用记事本也能打开，用 git 也能 diff。**

十年后你换了电脑、换了编辑器，\`.md\` 多半还在。
这不是情怀，是文件格式的半衰期。

### 本地优先，不是复古

本地优先（local-first）不是「拒绝一切网络」。
它是默认值的选择：

| 默认 | 含义 |
| --- | --- |
| 离线可写 | 没网也能完成一篇 |
| 文件在磁盘 | 路径你说了算 |
| 联网需明示 | AI、图床、同步都是你打开的开关 |

网络是插件，不是地基。

## 三、所见即所得，但不要重排我的字

写 Markdown 时，很多人讨厌「左源码、右预览」：视线来回跳，修改标点像在做校对兼职。

Typora 一类工具证明了另一条路：**在同一个页面里，源码与排版随光标切换。**

更进一步的要求是：

- 你改一个错别字，**不要**让整份列表符号被「规范化」
- 保存之后，git 里只应出现你动过的那几行

编辑器可以漂亮，但**漂亮不能以篡改文件为代价**。

## 四、AI 可以帮写，但不能默认劫持

AI 润色、续写、翻译，已经是日常。真正麻烦的是产品形态：

- 未说明就上传全文
- 静默覆盖，只能整段 Ctrl+Z
- Key 存在不明服务器

更克制的做法其实很简单：

1. **默认关闭**
2. **自带 API Key / 本机模型**
3. **发送前预览**将要出门的文字
4. **结果以 diff 呈现**，逐条接受或拒绝

AI 是副驾。方向盘在你手上。

## 五、一篇公众号长文需要的排版元件

下面这些，是排版验收时常用的「零件」。若它们都清楚、稳定，导出到 HTML/PDF 时就不会慌。

### 1. 小标题层级

#### 再短一点的小节标题

正文保持一行大约 20–40 个汉字的阅读节奏。句号后空一格不是必须，但**段落之间要留白**。

### 2. 强调与引用

这是**关键句**。这是*略作强调*。这是==需要读者停一下的高亮==。

> 好的标题负责把人留下。
> 好的结构负责把人送到底。
> —— 与工具无关，与训练有关

### 3. 有序与无序

写公众号常见结构：

1. 场景（读者是谁）
2. 冲突（他卡在哪）
3. 方法（你怎么解）
4. 行动（下一步做什么）

素材清单：

- 一个真实细节
- 一个可核对的事实
- 一个可执行的动作

### 4. 任务列表（编辑自用）

- [x] 标题不超过 20 字
- [x] 开头三行内出现冲突
- [ ] 配图位预留
- [ ] 末尾不写「总而言之」式空话

### 5. 代码（技术号专用）

\`\`\`bash
git clone https://github.com/YanXu2205/Inkstone.git
cd Inkstone
npm install
npm run dev
\`\`\`

### 6. 公式（偶尔用到）

信息熵的定义：$H(X) = -\\sum_i p_i \\log p_i$。

### 7. 一张结构图

\`\`\`mermaid
flowchart LR
  A[选题] --> B[提纲]
  B --> C[初稿]
  C --> D[删改]
  D --> E[标题与开头]
  E --> F[发布]
\`\`\`

### 8. 脚注

数据、引语、出处[^src]，能脚注就脚注，比「据说」更经得起追问。

[^src]: 脚注在公众号后台常被抹平；导出 HTML/PDF 时反而更完整。发布前按平台习惯改一遍即可。

## 结尾只留一件事

你不需要另一个「全能笔记操作系统」，
除非你的工作本来就是知识管理。

若你只是**写文章、写文档、写还没准备好公开的句子**——
选一个本地的、用纯文本的、打开就能写的工具，往往更长久。

保存，关闭，文件还在原来的文件夹里。
这就是我理解的、最低限度的写作自由。
